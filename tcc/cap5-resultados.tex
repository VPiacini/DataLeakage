\chapter{Results and Discussion}
\label{cap:resultados}

This chapter presents and discusses the results of the experiments described in
Chapter~\ref{cap:metodologia}. Section~\ref{sec:res-visao} compares the four
scenarios as a whole. Sections~\ref{sec:res-normalizacao}
to~\ref{sec:res-tuning} examine each scenario separately, with emphasis on why
leakage has, or does not have, an effect in each case.
Section~\ref{sec:res-algoritmos} compares the algorithms, and
Section~\ref{sec:res-datasets} relates the effects to the characteristics of the
data sets. Finally, Section~\ref{sec:res-discussao} answers the research
questions, compares the findings with those reported for classification, and
discusses the threats to the validity of the study. Throughout the chapter,
$\Delta R^2$ and $\Delta$RMSE follow Equation~\ref{eq:deltas}: positive values
indicate that leakage made the model look better than it is. The complete
numerical results are given in the tables of this chapter and of
Appendix~\ref{ap:tabelas}; the text focuses on the main patterns.

\section{Overview}
\label{sec:res-visao}

Table~\ref{tab:visao-geral} summarizes the effect of leakage in each scenario,
and Figure~\ref{fig:visao-geral} shows how the effect is distributed across data
sets and algorithms. The main observation is that the four scenarios behave in
very different ways, and that they form two clear groups.

In the first group are normalization and imputation. In both scenarios, the
pipelines with and without leakage produced almost the same estimates, the
average difference in $R^2$ was close to $2\times10^{-4}$, and the cases in which
leakage improved the estimate were about as frequent as the cases in which it
made the estimate worse. In the second group are feature selection and
hyperparameter tuning, the two scenarios that produced large distortions.
Hyperparameter tuning was the only scenario in which the effect was both frequent
and large: leakage improved the estimate in almost half of the pairs, and in the
worst case the difference in $R^2$ reached 0.35. Feature selection reached
similarly large differences, but only in a few cases, since in most pairs the
two pipelines produced exactly the same result.

This division matches the type of information that each step leaks
(Table~\ref{tab:fontes-vazamento}). Normalization and imputation use only
statistics of the features, such as means and standard deviations, which change
very little when the test instances are added to the training data. Feature
selection and hyperparameter tuning, on the other hand, use the target values to
make a decision: which features to keep and which configuration to report. When
the test instances take part in this decision, the pipeline can choose the
option that happens to work best on them, and the estimate becomes optimistic.
The following sections examine each scenario in more detail.

\section{Normalization}
\label{sec:res-normalizacao}

Table~\ref{tab:alg-normalizacao} presents the results of the normalization
scenario per algorithm. No algorithm showed a significant effect, and the
average differences were very small for all of them. This result can be
explained by how each algorithm uses the scale of the features.

Three of the five algorithms are not affected by the scale at all. The
predictions of LR do not change when the features are shifted and rescaled,
because the coefficients adjust to compensate for the transformation. Almost all
of its pairs were therefore exact ties, and the few remaining differences are
only rounding errors. DT and RF compare each feature with a threshold, and the
order of the values does not change under standardization. The small
differences observed for these two algorithms, in both directions, cannot come
from information about the test set; they come from numerical details of the
implementation, such as the order in which equivalent splits are evaluated. For
this reason, their size can be seen as the level of noise of the experimental
setup.

KNN and SVR depend on distances and margins, so they are sensitive to the scale
of the features, and the estimates of the two pipelines were never identical for
them. However, the differences favored the pipeline with leakage in about half of
the pairs and penalized it in the other half. Fitting the scaler on the full
data set therefore changed the estimates slightly, but did not make them
systematically better. The largest differences occurred in the smallest data
sets, such as \texttt{542\_pollution}, with only 60 instances, where the mean and
standard deviation of each feature change more when a few instances are added or
removed. The main conclusion of this scenario is that leakage in normalization
adds some variability to the estimate, mainly when the data set is very small,
but does not introduce a consistent bias.

\section{Missing Value Imputation}
\label{sec:res-imputacao}

The imputation scenario, summarized in Table~\ref{tab:alg-imputacao}, shows a
pattern similar to that of normalization: the effects are very small for all
algorithms. There is, however, one difference. In this scenario, leakage
improved the estimate a little more often than it worsened it, for all
algorithms. For SVR, this small but consistent shift was statistically
significant, although the average gain in $R^2$ remained below $10^{-3}$.

The imputation method had more influence on the result than the proportion of
missing values (Table~\ref{tab:alg-imputador} in Appendix~\ref{ap:tabelas}).
Mean and median imputation fill each missing value with a single number computed
from the whole column, and this number is practically the same whether or not
the test instances are included. The median, in particular, is often exactly the
same value, which produced many ties. KNN imputation works differently: it fills
each missing value using the most similar instances. When the imputer is fitted
on the full data set, a test instance can be filled with values taken from other
test instances, which brings training and test data closer together. As a
result, KNN imputation was the method with the largest effect, about four times
that of the other two, and with this imputer the effect on SVR was again
significant.

Contrary to what could be expected, increasing the proportion of missing values
did not increase the effect (Figure~\ref{fig:imputacao-taxa}). Two aspects of the
experimental setup help to explain this result and the small size of the
effects in general. First, only about one tenth of the features received missing
values (Section~\ref{sec:met-imputacao}), so most of the information used by the
models was never touched by the imputation step. Second, the statistics used by
the imputers are estimated almost equally well with or without the test
instances, so the extra information that leaks is small. Even so, the scenario
indicates that imputers based on individual instances, such as KNN, are more
prone to leakage than imputers based on summary statistics.

\section{Feature Selection}
\label{sec:res-selecao}

Feature selection produced the most uneven results of the four scenarios
(Table~\ref{tab:alg-selecao} and Figure~\ref{fig:heatmap-selecao}). In most pairs,
the pipelines with and without leakage selected exactly the same features and
therefore produced identical results. The reason is that the filter ranks the
features by their correlation with the target, and the best-ranked features are
usually the same whether or not the test instances are used. This is especially
true when only one feature is kept, which happens for the lowest percentiles and
for the data sets with few features. The effect only appears when more features
are kept, at the 10\% and 20\% levels, because then the features that compete
for the last positions of the ranking can be swapped by the presence of the test
instances (Figure~\ref{fig:selecao-percentil}).

When the effect does appear, however, it can be large. The most affected data
set was \texttt{542\_pollution}, which has only 60 instances
(Table~\ref{tab:top-selecao} in Appendix~\ref{ap:tabelas}). In one of its
configurations, the estimated $R^2$ of LR went from a negative value without
leakage, meaning that the model was worse than simply predicting the mean, to
about 0.5 with leakage, which suggests a model that explains half of the
variation of the target. This happens because, with so few instances, part of
the correlation between a feature and the target can be produced by chance by a
few test instances. When the selection is made on the full data set, these
features are chosen and then evaluated on the same instances that made them look
useful. This is the regression counterpart of the selection bias described by
\citeonline{ambroise2002} for classification. Smaller but still noticeable
effects were observed in other small data sets, such as \texttt{1089\_USCrime}.

Feature selection was also the only scenario in which leakage sometimes made the
estimate clearly \emph{worse}, as in \texttt{574\_house\_16H}. The filter used in
this work measures the \emph{linear} association between each feature and the
target, which is not necessarily what matters for non-linear models such as DT.
In large data sets, the rankings obtained with and without the test instances
are almost identical, and when a feature near the cutoff is swapped, the change
is not related to the test instances in any meaningful way and can favor either
pipeline. Because of these mixed results and of the large number of ties, no
algorithm showed a significant effect in this scenario. This lack of
significance should not be read as evidence that the step is safe: leakage in
feature selection is rare in this setup, but it can be severe when it occurs.

\section{Hyperparameter Tuning}
\label{sec:res-tuning}

Hyperparameter tuning was the scenario with the clearest and most consistent
effect (Table~\ref{tab:alg-tuning} and Figure~\ref{fig:heatmap-tuning}). The
non-nested procedure inflated the estimates of all five algorithms, and the
effect was statistically significant for all of them, both for $R^2$ and for
RMSE. In addition, the non-nested estimate was rarely worse than the nested one,
which shows that the error introduced by this kind of leakage almost always goes
in the same direction.

The reason for this consistency lies in how the non-nested procedure works. The
grid search evaluates several configurations with CV and reports the best score.
Each score contains some random error, and by reporting the highest one, the
procedure tends to select a configuration whose error happened to be favorable.
The more configurations have similar true performance, the more the choice
depends on this random error, and the more optimistic the reported score becomes.
Nested CV avoids this problem because the configuration is chosen in an inner
loop and evaluated on data that took no part in the choice.

The algorithms were affected in different ways. KNN and RF were affected most
often: their grids contain several configurations with similar performance, so
the selection described above almost always adds a small positive bias. The size
of this bias, however, was moderate. LR showed the opposite pattern. Most of its
pairs were exact ties, because its small grid often leads the nested and
non-nested searches to the same choice, and in that case both procedures report
the same score. When the choice was not stable, the effect was very large, and LR
had the highest average inflation of all algorithms.

The most affected cases occurred in small data sets (Table~\ref{tab:top-tuning}
in Appendix~\ref{ap:tabelas}). In \texttt{1096\_FacultySalaries}, with 50
instances, the non-nested procedure estimated an $R^2$ above 0.8 for LR and SVR,
while nested CV estimated values close to 0.5. In \texttt{505\_tecator}, which has
a large number of features compared with its number of instances, the RMSE of LR
was underestimated by about half. Part of this optimism also comes from the fact
that the non-nested pipeline reports, for each metric, the best value over the
grid, so it can choose a different configuration for $R^2$ and for RMSE. A
properly validated pipeline does not have this freedom.

\section{Sensitivity of the Algorithms}
\label{sec:res-algoritmos}

To check whether some algorithms are more sensitive than others, the Friedman
test was applied to the results of each scenario. A significant difference
between the algorithms was found only for hyperparameter tuning. In this
scenario, KNN had the best average rank, that is, it was the algorithm most
consistently affected, even though LR and SVR had the most extreme individual
cases. In the other scenarios, the differences between the algorithms were not
significant.

When the four scenarios are considered together, the results suggest that the
sensitivity of an algorithm depends on the kind of leakage and is not a fixed
property of the algorithm. KNN and SVR, which depend on the scale of the
features, are the only algorithms that react to leakage in normalization, but
this reaction is noisy and has no clear direction. SVR was the only algorithm with
a significant effect in imputation and was among the most affected in feature
selection and tuning, which makes it the algorithm affected most often across
scenarios. Tree-based models were the most robust overall: they do not depend on
the scale of the features, and RF had the smallest maximum effect in tuning. This
robustness of RF is consistent with the fact that it averages many trees, which
reduces the influence of any single decision of the pipeline. Finally, LR tends
to be either completely unaffected or strongly affected, depending on whether
the leakage changes the information available to it.

\section{Influence of Data Set Characteristics}
\label{sec:res-datasets}

Figure~\ref{fig:tamanho} relates the effect of leakage to the number of
instances of each data set. In all four scenarios, the largest effects are
concentrated on the left side of the plots, that is, in the smallest data sets.
The six data sets with fewer than 1,000 instances account for most of the
inflation observed in tuning and feature selection. Even in normalization and
imputation, where the average effect is close to zero, the differences between
the two pipelines are larger in the small data sets, which means that leakage
also makes the estimates less stable when data are scarce.

\begin{figure}[htb]
\centering
\includegraphics[width=\textwidth]{figuras/fig_delta_vs_size.pdf}
\caption{Mean $\Delta R^2$ per data set and algorithm versus the number of instances of the data set.}
\label{fig:tamanho}
\legend{Source: The Author. Spearman $\rho$ computed between the number of instances and the mean $\Delta R^2$ of each data set (averaged over algorithms). Vertical axis in symmetric logarithmic scale.}
\end{figure}

The Spearman correlations confirm this relation for hyperparameter tuning. The
effect was strongly and negatively correlated with the number of instances
($\rho = -0.82$) and positively correlated with the ratio between the number of
features and the number of instances ($\rho = 0.82$), while the number of
features alone showed no relation with it. For the other three scenarios, no
correlation was significant. In feature selection, this is explained by the fact
that the effect depends on a combination of conditions, namely few instances
\emph{and} enough features for the ranking to be unstable, which only a few data
sets satisfy.

These results have a simple interpretation. Both CV scores and feature rankings
are less reliable when they are computed from few instances. Leakage allows the
pipeline to choose, among several uncertain options, the one that happens to fit
the test instances best, and the greater the uncertainty, the greater the
advantage of this choice. In large data sets, all options are estimated
accurately, the choice made with the test instances is the same as the choice
made without them, and leakage has little practical consequence. This is an
important point for practitioners, because small data sets are common in many
applied areas, and they are exactly where a careless pipeline can produce the
most misleading results.

\section{Discussion}
\label{sec:res-discussao}

\subsection{Answers to the Research Questions}

\textbf{RQ1 -- Does leakage inflate performance estimates?} It depends on the
step. Leakage in hyperparameter tuning inflated the estimates of all five
algorithms in a significant way. Leakage in feature selection strongly inflated
the estimates in a few small data sets but left most configurations unchanged.
Leakage in normalization and imputation produced changes close to the level of
noise of the experiments, with a small but significant bias only for SVR in the
imputation scenario.

\textbf{RQ2 -- Which step produces the largest distortions?} Hyperparameter
tuning, both in frequency and in average size, followed by feature selection,
which reached similar maximum effects but much less often. Normalization and
imputation produced much smaller effects. This order follows the type of
information that leaks: steps that use the target are far more harmful than
steps that use only statistics of the features.

\textbf{RQ3 -- Are some algorithms more sensitive?} The algorithms differed
significantly only in the tuning scenario, where KNN was the most consistently
affected and LR and SVR showed the largest individual distortions. Across
scenarios, SVR was the algorithm affected most often, and tree-based models,
especially RF, were the least affected.

\textbf{RQ4 -- Do data set characteristics matter?} Yes. The number of instances
was the most relevant factor. The largest distortions occurred in data sets with
fewer than 1,000 instances, and, in the tuning scenario, the effect was strongly
related to the number of instances and to the ratio between features and
instances.

\subsection{Comparison with Classification}

\citeonline{becker2023} reported, for classification, that feature selection and
hyperparameter tuning were the steps with the largest effects and that SVM was
more sensitive than other algorithms. The present results agree on the first
point: in regression as well, the steps that use the target are the dangerous
ones. They also agree that the support vector family is among the most sensitive
algorithms. The main difference is the weight of feature selection, which in
this study produced severe distortions only in a few data sets. Part of this
difference can be explained by the design of the experiments, discussed in the
next subsection, and part by the continuous nature of the target. Since $R^2$
and RMSE depend on the exact value of every prediction, a small change in the
pipeline usually produces only a small change in the metric, whereas accuracy
changes in discrete steps. On the other hand, the error metrics of regression
have no upper limit, so in small data sets a single decision influenced by
leakage can change the RMSE by tens of percent, as observed in the tuning
scenario.

\subsection{Threats to Validity}

Some decisions of the experimental design limit the generality of the results.
Regarding \emph{internal validity}, the imputation scenario introduced missing
values in only about one tenth of the features and used a single mechanism
(MAR); a higher proportion of incomplete features or an MNAR mechanism could
produce larger effects. In addition, the random choice of which features receive
missing values is not controlled by the fixed seed used to generate the mask, so
this choice may vary between executions, although it is the same for the two
pipelines of each pair. The feature selection scenario used small percentiles
that, in data sets with few features, result in a single selected feature, which
reduces the number of informative configurations; it also used a hold-out
protocol, while the other scenarios used CV. Finally, outside the tuning scenario,
SVR was trained with a linear solver, so the conclusions about SVR in those
scenarios refer to linear SVR.

Regarding \emph{external validity}, the 21 data sets, although diverse, are a
small sample of regression problems, and only six of them have fewer than 1,000
instances, which is exactly the range where the effects appear. A larger number
of small data sets would allow the relation between size and leakage to be
described more precisely. Regarding \emph{conclusion validity}, the Wilcoxon
tests were performed with 21 data sets per algorithm, and the test discards ties,
which reduces its power in scenarios such as feature selection. For this reason,
the absence of significance in those scenarios should not be taken as evidence
that leakage is harmless.
