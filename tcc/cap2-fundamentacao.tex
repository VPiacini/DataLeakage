\section{Regression and Its Evaluation}
\label{sec:fund-regressao}

In supervised learning, an algorithm learns from a set of examples for which
the correct answer is known. Each example, or instance, is described by a set
of input features and has a known output, called the target. The algorithm uses
these examples to build a model that predicts the target of new instances. When
the target is a category (for example, ``sick'' or ``healthy''), the task is
called classification. When the target is a number (for example, the price of a
house or the fat percentage of a person), the task is called regression
\cite{hastie2009}. This work deals only with regression.

What matters in a model is how well it predicts instances that it has never
seen. A model that only memorizes the training data may look perfect on those
data and still fail on new ones. For this reason, a model is always evaluated
on data that were not used to train it, and the error measured on these data is
used as an estimate of how the model will behave in practice. This estimate is
called the generalization performance of the model.

In regression, the error of a prediction is the difference between the true
value and the predicted value. Considering $m$ evaluation instances with true
values $y_i$ and predicted values $\hat{y}_i$, the four metrics used in this work
are:

\begin{align}
  \text{MAE}  &= \frac{1}{m}\sum_{i=1}^{m} \lvert y_i - \hat{y}_i \rvert, \label{eq:mae}\\
  \text{MSE}  &= \frac{1}{m}\sum_{i=1}^{m} (y_i - \hat{y}_i)^2, \label{eq:mse}\\
  \text{RMSE} &= \sqrt{\text{MSE}}, \label{eq:rmse}\\
  R^2         &= 1 - \frac{\sum_{i=1}^{m} (y_i - \hat{y}_i)^2}{\sum_{i=1}^{m} (y_i - \bar{y})^2}, \label{eq:r2}
\end{align}

\noindent where $\bar{y}$ is the mean of the true values. The Mean Absolute Error
(MAE) is the average size of the errors. The Mean Squared Error (MSE) squares
each error before taking the average, so large errors weigh much more than
small ones. The Root Mean Squared Error (RMSE) is the square root of the MSE,
which brings the error back to the same unit as the target. For these three
metrics, lower values are better. They also depend on the scale of the target:
an RMSE of 10 is a small error when predicting house prices in dollars, but a
large one when predicting a percentage. Because of this, their values cannot be
compared between different data sets.

The coefficient of determination ($R^2$) solves this problem. It compares the
errors of the model with the errors of a very simple model that always predicts
the mean of the target. An $R^2$ of 1 means perfect predictions, an $R^2$ of 0
means that the model is no better than predicting the mean, and a negative
$R^2$ means that it is even worse than that. Since it does not depend on the
scale of the target, $R^2$ can be compared across data sets, and it is
considered more informative than the other metrics for this purpose
\cite{chicco2021}. For this reason, $R^2$ is the main metric of this work, and
RMSE is used as a complementary metric.

\section{Regression Algorithms}
\label{sec:fund-algoritmos}

Five algorithms were used in this work. They were chosen because each one
learns from data in a different way, which may also make them react
differently to data leakage.

\subsection{Linear Regression}

Linear Regression (LR) assumes that the target can be written as a weighted
sum of the features, $\hat{y} = \beta_0 + \beta_1 x_1 + \dots + \beta_d x_d$.
Training consists of finding the weights $\beta_j$ that make the squared errors
on the training data as small as possible, a method known as Ordinary Least
Squares (OLS) \cite{hastie2009}. LR is simple, fast, and has no
hyperparameters in its basic form. One property of LR is important for this
work: if a feature is shifted or multiplied by a constant, the model just
adjusts its weight, and the predictions stay exactly the same. Some variants add
restrictions to the weights, for example forcing all of them to be positive,
and these options can be treated as hyperparameters.

\subsection{K-Nearest Neighbors}

The K-Nearest Neighbors (KNN) algorithm does not build an explicit model. It
stores the training data and, to predict the target of a new instance, finds
the $K$ training instances that are closest to it and returns the average of
their targets \cite{cover1967,hastie2009}. Its main hyperparameters are the
number of neighbors $K$ and the distance used to measure how close two
instances are, such as the Euclidean or the Manhattan distance. Since distances
are computed directly from the feature values, a feature with large values (for
example, an income in dollars) will dominate a feature with small values (for
example, the number of rooms of a house). For this reason, KNN is very
sensitive to the scale of the features.

\subsection{Decision Trees}

A Decision Tree (DT) predicts the target by asking a sequence of simple
questions about the features, such as ``is the area of the house smaller than
100~m$^2$?''. At each node, the algorithm chooses the feature and the cut-off
value that best separate the training instances into groups with similar
targets. The process is repeated in each group until a stopping rule is reached,
and the prediction of each final group, called a leaf, is the mean target of its
training instances \cite{breiman1984}. Since each question only compares a
feature with a cut-off value, trees are not affected by the scale of the
features. On the other hand, a tree that is allowed to grow without limits ends
up memorizing the training data, so its size is usually controlled by
hyperparameters such as the maximum depth.

\subsection{Random Forests}

A Random Forest (RF) is a set of many decision trees whose predictions are
averaged \cite{breiman2001}. Each tree is trained on a random sample of the
training instances and, at each node, can only choose among a random subset of
the features. This randomness makes the trees different from each other, and
averaging many different trees gives more stable predictions than a single tree.
Like decision trees, random forests are not affected by the scale of the
features. Their main hyperparameters are the number of trees and the maximum
depth of each tree.

\subsection{Support Vector Regression}

Support Vector Regression (SVR) is the version of Support Vector Machines for
regression problems \cite{drucker1997,smola2004}. It looks for a function that
stays within a distance $\varepsilon$ of the true target for as many training
instances as possible, while being as simple as possible. Errors smaller than
$\varepsilon$ are ignored, and larger errors are penalized. The hyperparameter
$C$ controls how strongly these errors are penalized. With the use of kernels,
such as the linear kernel and the Radial Basis Function (RBF) kernel, SVR can
also learn non-linear relations. Since both $\varepsilon$ and the kernels depend
on the scale of the data, SVR usually needs the features, and often the target
as well, to be standardized before training.

\section{Building and Evaluating ML Pipelines}
\label{sec:fund-pipeline}

Raw data are rarely given directly to a learning algorithm. Before training,
they usually go through preparation steps, and the algorithm itself must be
configured and evaluated. The whole sequence, from the raw data to the final
performance estimate, is called an ML pipeline. This section describes the four
steps of the pipeline studied in this work and the methods used to evaluate a
model.

\subsection{Feature Scaling}

The features of a data set often have very different ranges. In a data set of
houses, for example, the area may vary between 30 and 500, while the number of
bathrooms varies between 1 and 4. Scaling puts all features in a similar range.
The most common method, called standardization or $z$-score, transforms each
feature $x_j$ as follows:
\begin{equation}
  x'_j = \frac{x_j - \mu_j}{\sigma_j},
  \label{eq:zscore}
\end{equation}
where $\mu_j$ is the mean and $\sigma_j$ is the standard deviation of the
feature. After this transformation, every feature has mean 0 and standard
deviation 1. An important detail is that $\mu_j$ and $\sigma_j$ are computed
from the data. In other words, the scaler also ``learns'' something from the
data before it can be used, and the data used for this purpose make a
difference, as discussed in Section~\ref{sec:fund-vazamento}.

\subsection{Missing Value Imputation}

Real data sets often have missing values, for example a sensor that failed or
a question left blank in a survey. Most algorithms cannot work with missing
values, so they must be filled in before training, a process called
imputation. The way values go missing is usually classified into three types
\cite{rubin1976,little2019}: missing completely at random (MCAR), when the
chance of a value being missing has no relation with the data; missing at random
(MAR), when this chance depends on other features that are observed; and missing
not at random (MNAR), when it depends on the missing value itself, for example
when people with high incomes tend not to report their income.

The simplest imputation methods replace each missing value with the mean or the
median of the observed values of the same feature. A more elaborate method, the
KNN imputer, looks for the $K$ instances most similar to the incomplete one and
uses the average of their values \cite{troyanskaya2001}. As with scaling, all
these methods learn something from the data (a mean, a median, or a set of
neighbors) before they can fill in the missing values.

\subsection{Feature Selection}

Feature selection keeps only the most useful features of a data set and
discards the others. Using fewer features can make models simpler, faster, and
sometimes more accurate \cite{guyon2003}. A common and simple approach, used in
this work, is to give each feature a score that measures how strongly it is
related to the target and to keep the features with the highest scores. In
regression, a typical score is given by the $F$-test, which measures the linear
relation between each feature and the target. Unlike scaling and imputation,
this step uses the values of the target to decide which features are kept.

\subsection{Hyperparameter Tuning}

Hyperparameters are settings of an algorithm that are chosen before training,
such as the number of neighbors in KNN, the maximum depth of a tree, or the
values of $C$ and the kernel in SVR. Hyperparameter tuning is the process of
trying different values and keeping the ones that give the best performance.
The most common strategy is grid search, which tests every combination of
values in a predefined list; random search, which tests random combinations, is
a frequent alternative \cite{bergstra2012}. To compare the combinations, each one
must be evaluated on data that were not used to train it, so tuning also needs
one of the evaluation methods described below.

\subsection{Model Evaluation}

The simplest way to evaluate a model is the hold-out method: the data are split
once into a training set, used to build the model, and a test set, used only to
measure its performance. The result, however, depends on how the data happened
to be split, which is a problem for small data sets. In $k$-fold
cross-validation (CV), the data are divided into $k$ parts of similar size,
called folds. The model is trained $k$ times, each time using $k-1$ folds for
training and the remaining fold for testing, and the final result is the average
of the $k$ tests \cite{kohavi1995,hastie2009}. This way, every instance is used
once for testing. The whole process can also be repeated with different random
splits to obtain a more stable result.

A common mistake is to use the same CV both to choose the hyperparameters and
to report the performance of the chosen model. In this case, the reported
value is the best one among many tested combinations, and part of this good
result is just luck, so the estimate is too optimistic
\cite{varma2006,cawley2010}. Nested CV avoids this problem by using two levels
of CV. The outer level splits the data into training and test folds, as in a
normal CV. Inside each outer training fold, an inner CV is used to choose the
hyperparameters. The chosen model is then evaluated on the outer test fold,
which did not take part in the choice. Nested CV is more expensive, since many
more models must be trained, but it gives an almost unbiased estimate of the
performance of the whole tuning process \cite{varma2006}.

\section{Data Leakage in ML Pipelines}
\label{sec:fund-vazamento}

All the evaluation methods above rely on one simple rule: the data used to test
a model must not be used in any way to build it. Data leakage happens when this
rule is broken, that is, when information that would not be available when the
model is used in practice is used during its development \cite{kaufman2012}.
Some cases of leakage are easy to see, such as a feature that contains the
target itself, or the same record appearing in both the training and the test
sets. Others are much harder to notice. \citeonline{kapoor2023} describe, among
other types, the leakage that occurs when training and test data are not kept
separate during pre-processing, for example when a step is applied to the whole
data set before it is split.

This last type of leakage is the focus of this work. As seen in
Section~\ref{sec:fund-pipeline}, the scaler, the imputer, the feature selector,
and the tuning procedure all learn something from the data. In a correct
pipeline, each of them is fitted using only the training data of each split, and
then applied to the test data without any change. In a pipeline with leakage,
the same step is fitted once on the whole data set, and only then are the data
split. As a result, the test instances help to shape the model that they are
supposed to evaluate. Table~\ref{tab:fontes-vazamento} shows, for each step,
what is learned from the data and what information from the test set reaches
the model when leakage occurs.

\begin{table}[htb]
\centering

\small
\begin{tabular}{p{2.6cm}p{5.0cm}p{6.2cm}}
\toprule
\textbf{Step} & \textbf{Learned from data} & \textbf{Information leaked from the test set} \\

The table suggests that the four steps are not equally dangerous. Scaling and
imputation only leak information about the features. If the training and test
instances come from the same population, the training data alone already give a
good idea of this information, so the test data add little. Feature selection
and hyperparameter tuning, on the other hand, leak information related to the
target, either directly or through the performance of the model. This allows the
pipeline to adapt itself to the specific test instances, which can make the
model look much better than it really is. Chapter~\ref{cap:resultados} tests
these expectations with experiments.

\section{Statistical Tests}
\label{sec:fund-estatistica}

In this work, each pipeline with leakage is compared with a pipeline without
leakage run on exactly the same data split, which produces pairs of results. The
Wilcoxon signed-rank test \cite{wilcoxon1945} checks whether the differences
within these pairs tend to be positive or negative, or whether they are
centered around zero. It works with the ranks of the differences instead of
their values, so it does not assume that the differences follow a normal
distribution and is not much affected by a few extreme values.
\citeonline{demsar2006} recommends this test to compare two methods over several
data sets, using one value per data set. Pairs with a difference of exactly zero
are ignored by the test, so many ties reduce the amount of data it can use.

To compare more than two methods over the same data sets, such as the five
algorithms of this work, the Friedman test \cite{friedman1937} can be used. It
ranks the methods in each data set and checks whether some methods have
consistently better (or worse) ranks than others \cite{demsar2006}.

When many tests are performed, some of them will give a significant result just
by chance. The Holm method \cite{holm1979} corrects the $p$-values to take the
number of tests into account, and it is less strict than the well-known
Bonferroni correction. Finally, the Spearman correlation coefficient $\rho$
\cite{spearman1904} measures whether two quantities tend to increase or decrease
together. In this work, it is used to check whether the effect of leakage is
related to characteristics of the data sets, such as their number of instances.
